# Decisions

One line each: decision, why, what it costs.

- **psycopg 3 + sync SQLAlchemy** — one driver, sync sessions everywhere; costs: no async DB access, every route runs on threadpool workers.
- **TTS_* optional until M4** — `TTS_BASE_URL`/`TTS_DEFAULT_VOICE` have no defaults in the spec but the M1–M2 stack must boot without a TTS backend; validated when the TTS client is first constructed; costs: a TTS misconfiguration surfaces at M4, not at start-up.
- **`FOLIO_TEST_MODE` test-login endpoint** — headless tests/e2e need a session without a real LDAP server; `POST /api/v1/test/login` is mounted only when the flag is true and only `compose.test.yaml` may set it; costs: a test-only attack surface if the flag ever ships to production.
- **Gitignored generated fixture books** — binaries bloat the repo and public-domain texts must not be committed; `make fixtures` regenerates all seven; costs: a first `make test` needs `make fixtures` first.
- **CI deferred to M6** — no pipeline config until the stack is stable; checks run locally via `make lint`/`make test`; costs: regressions depend on developer discipline until M6.
- **React 19 instead of the spec's React 18** — current major, same API for everything Folio uses; costs: none expected, only third-party peer-dependency friction.
- **Tailwind 4 CSS-first tokens** — theme lives in `tokens.css` via `@theme`, no `tailwind.config.js`; costs: config-file examples from older Tailwind don't apply.
- **PyMuPDF pinned to 1.26** — 2.0 removed the legacy `fitz` module; import `pymupdf`; costs: capped below 2.x until its API settles.
- **Tags in the FTS index via an IMMUTABLE wrapper function** — the expression index needs an immutable expression to fold `books.tags` into the searchable text; costs: one extra SQL function that must stay in sync with the index definition in migrations.
- **pysbd language fallback via `LANGUAGE_CODES`** — pysbd raises `ValueError` on unknown ISO codes, so `segment.py` checks the base language (`language.split("-")[0]`) against pysbd's supported set and falls back to `en`; costs: a book tagged with an unsupported language is segmented with English rules silently.
- **Segments are exact chapter-text substrings** — every sentence/segment satisfies `text[char_start:char_end] == piece.text`, so packed segments keep the whitespace between their sentences; costs: TTS input may carry leading/trailing spaces or paragraph newlines (harmless for speech, required for progress percentages).
- **Duck-typed chapters in `clean_chapters`** — `clean`/`segment` take any object with `.title`/`.text` and `clean_chapters` rebuilds via `dataclasses.replace` to preserve the input type; costs: chapters must stay dataclasses with a `text` field.
- **`TEST_DATABASE_URL` + auto-created `folio_test`** — the harness connects to the server's `postgres` db and creates the test database when missing, so `make test` works on a fresh box; costs: the folio role needs CREATEDB rights on the dev server.
- **Detection-only AZW3 stub when Calibre is absent** — `make_fixtures` writes a minimal PalmDB file with the `BOOKMOBI` magic so all seven fixture keys always exist and `detect_format` is testable; costs: `extract_kindle` tests must skip without Calibre (real conversion runs in the Docker image).
- **Embedded ffmpeg-generated silent Ogg/Opus in `mock_tts.py`** — one 1-second real Opus file as base64, no network or runtime encoder needed; costs: the bytes are frozen; regenerate with `ffmpeg -f lavfi -i anullsrc=r=48000:cl=mono -t 1 -c:a libopus` if ever needed.
- **`asyncio_mode = auto` in `pyproject.toml`** — async `client` fixtures work without per-test decorators; costs: none.
- **Shared ingest types in `folio/ingest/__init__.py`** — Task 5a's file list has no `types.py` and the readers must not import each other; costs: the package `__init__` is the public surface for `ExtractedBook`/`UnsupportedFormat`/`ScannedPDF`.
- **Kindle metadata via `ebook-meta` text parsing** — the plan pins `ebook-meta` for fields the converted EPUB lacks; we parse its stable `Key : value` output and only fill empty fields; costs: breaks if Calibre changes its output format, first author only.
- **PDF front matter before the first outline entry is dropped** — outline entries define chapter starts; costs: a title page ahead of the first bookmark is not spoken.
- **React 19 (19.3.1), not the spec's React 18** — pinned by the M1–M2 plan; the spec table predates the plan; costs: none known, `@types/react` 19 conventions (ref as prop) apply.
- **ESLint 10 flat config (`eslint.config.js`)** — `.eslintrc.cjs` is removed in ESLint 9+; the plan's file list predates the pin; costs: none, config lives in one file.
- **Theme via `[data-theme]` + semantic CSS vars, no `dark:` variants** — components consume `bg-page`/`text-ink`/`text-muted` mapped through `@theme inline`, so light/dark flips cascade from one token block; costs: brand-specific dark tweaks need a new token instead of a `dark:` class.
- **Admin jobs table accepts bare array or `{items}`** — `GET /admin/jobs` response shape isn't pinned until T2 merges; costs: drop the normalization once the backend contract lands.
- **Job statuses `queued → running → done | failed`** — the spec pins the `jobs` columns but not the status vocabulary; costs: the M3 admin jobs table must map these values to labels.
- **`jobs.notify` commits before/while sending** — Postgres delivers NOTIFY only at transaction end, so a caller's open transaction would silently drop the event; costs: `notify` cannot be part of a larger atomic unit.
- **`worker.run_once(session, settings) -> bool`** — the claim/dispatch/finish/notify body is extracted from `main()` so tests drive one iteration without threads or signals; costs: one extra module-level function beyond the plan's pinned surface.
- **CSRF token = HMAC-SHA256(secret, session_id)** — deterministic, stored on the session row and compared with `secrets.compare_digest` against the `X-CSRF-Token` header (double-submit); the test-mode login uses the same derivation; costs: rotating `FOLIO_SECRET_KEY` invalidates every live CSRF token (users must re-login).
- **Login rate limiting is in-process, keyed by lowercased username** — 10 failures per 15 min trigger a 15-min lockout checked before any LDAP contact; no Redis by design; costs: state is per uvicorn worker and lost on restart (documented `ponytail:` note to move to a DB table if ever scaled out).
- **All LDAP bind/transport failures map to `invalid_credentials`** — the spec forbids revealing which step failed, so server outages look like bad passwords to clients; costs: operators must read logs (username + failure class only) to tell the two apart.
- **Sliding session expiry refreshes at most hourly** — `get_current_user` pushes `expires_at` out to now+30d only when it has drifted below now+30d−1h; costs: one extra write per hour per active session instead of one per request.
- **Upload uses XHR, not the fetch client** — `fetch` has no upload-progress events, so `useUpload` in `api/books.ts` posts one file per `XMLHttpRequest` and reuses the exported `csrfToken` from `api/client.ts`; costs: the error-envelope unwrapping exists twice.
- **SSE frames only invalidate TanStack queries** — `useEvents` (mounted once in AppShell) invalidates `["books"]` and `["book", id]` instead of maintaining a client-side status store; costs: a frame triggers one GET per mounted book query.
- **Reprocess/Delete shown for admins only** — the spec also allows the uploader, but the `Book` payload does not expose `uploaded_by`; costs: uploaders cannot reprocess their own books until the payload (or a `can_edit` flag) lands.
- **Upload rows read status through `useBook`** — after the POST returns, each row's badge comes from the book query invalidated by SSE, not from the frame's `status` field; costs: the badge needs the book query to refetch, one extra GET per finished book.
- **`process_book` takes a Job or a book UUID** — the plan pins `process_book(session, settings, book_id)` while the worker's `Handler` type passes a `Job`; the third parameter accepts both so `HANDLERS = {"ingest": process_book}` keeps its type; costs: one `isinstance` line and two spellings of one call.
- **`python-multipart` added to the pinned dependencies** — FastAPI raises at import time for any `UploadFile`/form route without it, and the plan's dependency list omitted it; costs: one more pinned package in the image.
- **Upload dedupe returns the existing book with `job_id: null` and creates nothing** — the spec says "link to the existing book"; a second ingest job would only redo work; costs: the client must treat `duplicate_of` as success, not error.
- **SSE: one psycopg LISTEN connection and one daemon thread per client** — trivial at the spec's 10-user scale and needs no shared broker; `LISTEN` runs before the mid-ingest snapshot so a frame can duplicate but never be missed; costs: connection count grows with open tabs (`ponytail:` note in `folio/events.py`).
- **`cover_key` is the sha256 of the cover bytes** — doubles as the ETag and the `?v=` cache-buster, and a replaced cover changes the URL for free; costs: none known.
- **Catalog author sort uses `authors[1]`** — Postgres arrays are 1-based and SQLAlchemy passes the subscript through; books without authors sort last (ASC NULLS LAST default); costs: multi-author books sort by their first author only.
- **AD username handling borrowed from the working `notely` integration** — accept `DOMAIN\user`, `user@domain` and bare names, support `{upn}` in the filter (domain derived from the `dc=` base), key the local user row on the directory's canonical `sAMAccountName`/`uid`, require exactly one search result, and set `get_info=None` + `auto_referrals=False`; costs: none — this closes a duplicate-user bug for case/spelling variants and a referral-hang risk.
- **Find-metadata sends title+author joined into `q`** — the pinned search contract is `q=&isbn=` with no separate author parameter; costs: provider relevance depends on the joined string.
- **Apply checkboxes omit `cover_url`** — the contract leaves `fields[]` unenumerated and books store `cover_key`, not a URL, so provider covers go through the cover editor's URL fetch instead; costs: one extra step to take a match's cover.
- **Edit / Find metadata shown to every signed-in user** — the server enforces uploader-or-admin and the 403 message renders inline; costs: users see buttons they may not be permitted to use.
- **Crop exports via a detached 1200x1800 canvas to WebP** — no dependency; browsers without WebP encoding silently fall back to PNG, which the server's magic-byte check accepts; costs: the encoded bytes are not byte-identical to Pillow's WebP.
- **Metadata form lives in `EditBookPage.tsx`, not `MetadataFields.tsx`** — the plan's file list predates Task D's pinned build list and one use site does not earn a file; costs: none until a second form appears.
- **M3 description edits are stored as plain text** — `PATCH /books/{id}` runs `bleach.clean(tags=[], strip=True)` like the pipeline already does, so no HTML survives; the spec allows sanitized HTML; costs: rich descriptions from online sources lose their markup, add an allowlist when the UI renders descriptions.
- **Per-workstream test databases** — parallel agents share one Postgres server but never one database (`folio_test_<workstream>`), because concurrent `TRUNCATE ... CASCADE` and ingestion tests deadlock and produce phantom `FileNotFoundError`s; costs: one extra database per active worktree, created automatically and dropped by hand.
- **Cover URL downloads guard schemes and redirect count, not internal IPs** — pasted cover URLs are rejected unless http(s), redirects are capped at 5, and the body is streamed with a 10 MB cap; a homelab admin can still point Folio at an internal host by design; costs: SSRF to internal services remains possible for editors, acceptable for a self-hosted admin-only feature.
- **Embedded covers that fail JPEG/PNG/WebP validation are skipped, not fatal** — `pipeline._store_cover` swallows `cover_invalid` so a GIF or broken embedded image leaves the book cover-less instead of failing ingestion; costs: a book with only an exotic embedded cover shows the placeholder until one is uploaded.
- **`GET /books/{id}/cover` now lives in `routers/covers.py` and the ETag is `"<cover_key>-<size>"`** — the M2 endpoint in `routers/books.py` ignored `size`; the covers router is mounted before the books router so it wins the shared path; costs: the dead M2 handler stays in `books.py` until the lead removes it at merge.
- **Upload oversize covers are 413 `cover_too_large`, every other cover rejection is 422 `cover_invalid`** — the plan pins 413 for >10 MB uploads but only names `cover_invalid`; costs: the frontend must map two codes for the cover editor.
- **Metadata providers never raise: a non-200, timeout or parse error is "no results"** — one shared `metadata.get_json` logs at warning and returns `None`, so Google Books' keyless 429 on this network (and any Open Library outage) degrades to an empty candidate list; costs: a misconfigured or rate-limited source is invisible except in logs.
- **`apply_candidate` never writes `locked_fields` and never locks anything itself** — a manual "Find metadata" apply is re-appliable (a later apply can change your mind), and only `PATCH /books/{id}` records a field as hand-edited; costs: an applied field is not protected from a later ingest auto-fetch unless the user also edited it.
- **ISBN auto-match compares same-field normalized digits (13↔13, 10↔10), no cross-conversion** — cheap and unambiguous; costs: a book that stores only ISBN-10 will not auto-match a candidate that only exposes ISBN-13 (it becomes a review candidate instead).
- **Auto cover fetch uses the best candidate whether it auto-applied or is only the top review match** — honours the plan's "chosen/expected candidate" wording so an ISBN EPUB gets a cover with no human step; costs: a below-threshold top match can still attach its cover, which the user can replace in the editor.
- **`MetadataCandidate` lives in `folio/models/metadata.py` (not in the plan's file list)** — the test harness uses `Base.metadata.create_all`, so the table must be a mapped model; migration `0003` mirrors it; costs: one extra model file beyond the plan.
- **Open Library ISO-639-2 codes are mapped to BCP-47 for the handful of voice languages, others pass through** — `eng→en`, `jpn→ja`, `kor→ko`, `chi/zho→zh`, etc.; costs: an unmapped language code is stored verbatim and falls back to English segmentation.
- **`previewVoice` calls `fetch` directly** — the api client parses JSON only and `POST /voices/preview` answers with audio bytes; it reuses `csrfToken`/`ApiError` so the header and error envelope stay identical to the client; costs: the envelope unwrap is duplicated in one place.
- **Voice types live in `api/voices.ts`, not `api/types.ts`** — `types.ts` is owned by the player workstream this milestone and voices have exactly one consumer surface; costs: a second type home until M5 consolidates.
- **Settings voices and default speed persist to localStorage (`folio-voice-<lang>`, `folio-speed`)** — the user-settings API is M5; the player reads the same keys; costs: these settings are per-device until M5 sync.
- **The "Refresh voices" button is a mutation that `setQueryData`s into the pickers' cache key** — two `useVoices` observers with different queryFns on one key would race over which fetch wins; costs: opening Settings fires two GETs (cached list + refresh).
- **`useTheme` gained `choice`/`select` ("system" | "light" | "dark")** — Screen 8 needs three states while AppShell's toggle stays unchanged; costs: "system" no longer writes `folio-theme` on mount, the pin is explicit-only.
- **The player opens its own EventSource for `audio` frames instead of extending `useEvents`** — Task C owns the player module, not the shell's SSE hook, and a second listener there would collide with the voices workstream; costs: two SSE connections per tab, consolidate if the server ever caps them.
- **`lead_in` from `prepare` is fetched but not played** — Task B has not pinned whether chapter titles are also segment 0, and playing both would speak the title twice; costs: spoken chapter titles stay dark until M5 wires the lead-in (or the backend folds it into segments).
- **Player state lives in a mutable ref bumped into React, not useState** — the `<audio>` event handlers need the live state machine without rebinding listeners every tick; costs: no per-field memoization and every bump re-renders the subtree.
- **`Voice.available` marks engine-confirmed voices; the `TTS_VOICES` fallback is `available=False`** — the engine is the source of truth, so a voice it lists is available and one we only know from config is not; `select_voice` matches by id membership (not the flag), so a fallback voice is still selectable while a voice the engine dropped falls through; costs: the flag is a UI hint only, T-D reads it for "No longer available".
- **The voice-payload parser lives in `voices.py` (`parse_voices_payload`) and `TtsClient.list_voices` calls it** — the plan attributes shape-parsing to `discover_voices`, but the client must return `list[Voice]` too, so one parser is shared instead of duplicated; costs: `list_voices` does the endpoint probing and parsing, `discover_voices` adds the TTL cache and `TTS_VOICES` fallback on top.
- **Cache key uses the requested format, the row stores the actual one** — the key is `sha256(model|voice|settings.tts_format|normalized)` computed before synthesis, so an opus→mp3 fallback still lands on a stable key and is found on later hits; the `format`/`path` columns record the bytes actually written; costs: an entry's key format can differ from its file extension when the engine rejects opus.
- **`prepare_for_speech` is an alias of `normalize_speech_text`** — the plan pins both names for the one preparation step; costs: two spellings of one function.
- **Honorifics expand only before a capitalised name** (`Dr. Who`→`Doctor Who`, bare `the Dr.` untouched); `Mrs`→`Mistress`, `Ms`→`Miss`, `e.g.`→`for example`, `i.e.`→`that is` — "safe positions" per the spec so a mid-sentence abbreviation is never mis-expanded; costs: an honorific before a lowercase word stays abbreviated.
- **`TtsClient` keeps the pinned `TtsClient(settings)` signature and owns its `httpx.Client`** — tests inject `httpx.MockTransport` by swapping the private `_client` (reusing the built headers) rather than adding an unpinned `transport=` argument; costs: one private-attribute touch in the test helper.
- **Range streaming delegates to Starlette's `FileResponse`** — it implements 206/`Content-Range`/416 and `Accept-Ranges` natively (RFC 7233), so Folio writes none of that; costs: a syntactically malformed `Range` header answers 400, only unsatisfiable ranges get 416.
- **The admin health `tts` probe lives in `routers/admin.py`, the endpoint stays in `main.py`** — `admin_health` is reachable by any signed-in user (the harness pins that), while `admin_router` enforces admin on every route; moving it would change auth; costs: one `main.py` line calls `probe_tts(settings)`.
- **`Audio.last_played_at` is touched at most once per minute per key via an in-process dict** — eviction is LRU-minute-grained, so per-request writes are waste; costs: state is per API worker and resets on restart (one extra touch).
- **`prepare` never re-queues a `failed` row** — only the player's retry button does, so a permanently failing segment cannot spin the GPU forever; costs: an unattended listener sees "Couldn't generate this part" until someone taps retry.
- **`retry` without a voice resets the segment's most recent failed row** — the row already knows its voice, so the endpoint needs no voice discovery; costs: with two failed voices for one segment, only the newest is retried.
- **Live synthesis smoke is `scripts/live_tts_smoke.py`, not a test** — the suite must never reach the network; the script hits the real engine on demand and prints bytes/duration.
- **Listening-settings hooks live in `api/settings.ts`, not `hooks/useListeningSettings.ts`** — the query, mutation, type and defaults stay colocated like `api/voices.ts`; costs: the plan's Task R file list names one path that does not exist.
- **The offline fallback is inside `useListeningSettings`'s `queryFn` (catch → localStorage mirror), so the query never enters an error state** — the player and Settings render defaults/mirror without blocking on a failed GET; costs: a server error is indistinguishable from offline in the cache, so the page cannot show a distinct "server unreachable" note.
- **Skip intervals are applied in `PlayerProvider` (`skipBack`/`skipForward` read the settings ref) and `FullPlayer` just calls them** — the configured values take effect on the next interaction with no reload and are testable at the provider level; costs: `FullPlayer.tsx` (not in Task R's file list) was touched to wire the buttons/keys.
- **Editing one language's voice PUTs the whole `voices` map, not a per-key patch** — the server merges top-level JSONB keys, so sending the full map is correct under both shallow and deep merge; costs: concurrent per-language edits from two devices last-write-win on the entire map.
- **`ahead_of_other_device` compares character positions (chapter `idx` + segment `char_start`) converted at `TTS_CHARS_PER_SECOND`, ignoring `offset_s`** — the plan pins percent and position to characters, so the 60 s rule uses the same ruler; costs: a second save inside the same segment at a different second-offset never prompts.
- **`PUT /books/{id}/progress/finished` returns `{progress}` and 404s when no progress row exists** — `chapter_id`/`segment_id` are NOT NULL, so "finished" without a position is not a row we can store; costs: the player must save progress before marking finished (it does, at the last segment's end).
- **`PUT /me/settings` rejects unknown keys (`extra="forbid"`)** — a typo would otherwise persist junk into the JSONB and shadow a future default; costs: a new setting key needs a server deploy before the client can send it.
- **Progress saves use `fetch(..., { keepalive: true })` with the CSRF header, not `sendBeacon`** — the spec suggests `sendBeacon`, but beacons cannot set `X-CSRF-Token` and every state-changing route requires it; keepalive lets the save survive tab-hide/page unload; costs: one fetch call site outside `api/client.ts` (reuses its exported `csrfToken`).
- **Device label = `navigator.platform` + 4-char id in `localStorage["folio-device"]`** — stable per browser for the ahead-of-device prompt, capped at 64 chars; costs: the label survives logout and two users of one browser are indistinguishable by label.
- **The cross-device ahead check is client-side (percent gap × duration estimate > 60 s)** — `GET /progress` carries no ahead flag (only PUT returns one) and the prompt must fire before the first save; this device's position is mirrored in `localStorage["folio-pos-<bookId>"]`; costs: the 60 s threshold rides on the chars/second estimate, so it is approximate for books with unusual speech rates.
- **Finished books surface as a badge on Continue cards and the book page, not a "Finished" shelf** — `/me/continue` excludes finished books and no endpoint lists finished books; costs: a browsable Finished section needs a backend list in M6.
- **`pump()` never starts audio while something is playing; the only handoff is `handleEnded` (stop, swap `active`, pump)** — SSE/poll `topUp` used to pump the idle (preloaded) element mid-playback, so both elements played, the next sentence overlapped, and `pause` left one running; costs: a seek or chapter switch while playing restarts the current segment in the same element (one short glitch instead of overlap).
- **The mini player renders at every viewport (64px bar, `max-w-5xl` content, pinned to the viewport bottom on md+)** — `md:hidden` made it invisible on desktop where it is the only transport UI; costs: `AppShell`'s main keeps `pb-32 md:pb-20` bottom padding whenever a book is loaded, even on `/player` where the bar is hidden.
- **Chapter exclude/include is optimistic in the `["book", id]` cache and never refetch-invalidated** — the pinned contract says excluded chapters are omitted from `GET /books/{id}`, so a refetch would make them impossible to re-enable; costs: excluded rows vanish from the book page after a reload until the backend returns them with `excluded: true`.
- **Read-along font step lives in `localStorage["folio-readalong-font"]` (3 steps), not `/me/settings`** — the pinned settings contract has no key for it and `PUT /me/settings` rejects unknown keys; costs: the text size does not sync across devices.
- **The book page's sticky action bar offsets itself by the bottom nav and, when the player holds a book, by the mini player's 3.5 rem height** — `MiniPlayer` is owned by another workstream, so the offset is a constant, not a measurement; costs: a mini-player height change needs the two `bottom-[calc(...)]` classes touched.
- **The chapter manager is shown to admins only** — the `Book` payload exposes no `uploaded_by`, matching the existing TODO(M5) for Reprocess/Delete; costs: uploaders see no switches until the payload grows the field.
- **`metadata_search` scores candidates against the book at request time** — providers' relevance order means nothing to the user and `score_candidate` was only run by `auto_fetch`, so the UI showed 0 %; costs: one in-memory scoring pass per search.
- **`apply_candidate` fetches the candidate cover whenever the book has none, even if `cover_url` was not in `fields`** — the demo apply left the cover empty because the UI never requests that field; an explicit `cover_url` still overwrites an existing cover; costs: one extra download on the first apply of a candidate with a cover.
- **Non-English voice previews are pure target-language text (no "Folio")** — a Latin word in the sample gets read in English by the engine (demo finding); costs: the brand name is absent from non-English previews.
- **Excluding a chapter recomputes `total_chars`/`est_duration_s` and `_chars_before` skips excluded chapters** — progress percent is measured against what actually plays; costs: stored `percent` values only update on the next progress PUT.
- **Excluded chapters stay in `GET /books/{id}` with an `excluded` flag but 404 on segments** — the UI needs them listed to re-enable, while playback must never fetch them; costs: every chapter list carries the hidden rows.
- **VoicePicker lists only voices tagged with the target language — no Default (null) option, no Show-all toggle, `tts` hidden** — the engine's language-agnostic `tts` default mispronounces non-English text, so "Default" was a trap; with nothing saved the picker *displays* the first available voice of the language but calls `onChange` only on an explicit pick; costs: `settings.voices` stays empty until the user acts, and the voice actually synthesized for such a book is whatever the backend defaults to.
- **The reader panel markup lives in `ReadAlong.tsx`, not `FullPlayer.tsx`** — the panel is the component's own scroll container and auto-scroll needs its ref; costs: FullPlayer's JSX no longer shows the reader's chrome.
- **Reading text uses a system serif stack (`--font-reading`)** — DESIGN.md forbade a serif *dependency*, and `ui-serif`/Georgia are not one; costs: exact glyph look varies per platform.
- **Auto-scroll moves `panel.scrollTop` (`scrollTo({top: offsetTop − clientHeight/2})`) instead of `scrollIntoView`** — `scrollIntoView` scrolls every ancestor, which jumped the window; costs: the panel must stay the reader's only scroll container.
- **`chapterDuration` is renamed `chapterTotal` in the player context** — the mini player shows `elapsed / total` and the pair needs one obvious name; costs: a renamed context field (one call site).
- **`stop()` saves progress before clearing the book** — pause saves, so stop must not silently lose up to 10 s of position; costs: one progress PUT per stop.
- **`ChapterSheet` deleted in favor of a native chapter `<select>`** — one always-visible control replaces a tap-to-open sheet and the native picker works on every viewport; costs: the per-chapter estimated lengths the sheet showed are gone.
- **The mini player stays 64 px (`h-16`)** — the book page's action bar offsets by the mini player's 3.5 rem constant (see above), so a height change would touch files outside this workstream; costs: the bottom of the 64–72 px target.
- **The book page drops its fixed bottom action bar for a cover play overlay + percent badge** — the mini player is the persistent transport, so a second Play/progress bar duplicated it; costs: Play lives on the cover, and the overlay must stay a `link` named "Play" for the e2e playback checks.
- **The chapter accordion became a native `<select aria-label="Chapters">` with prev/next buttons that navigate to `/player?book&chapter`** — a dropdown is the lazy, accessible chapter picker and reuses the player URL contract; costs: excluded chapters are absent from the picker (they are re-enabled in Book settings).
- **Pronunciation-rule text edits commit on blur, flags commit on change** — a PATCH per keystroke would hammer the endpoint, while a checkbox is one discrete choice; costs: an uncommitted text edit is lost on blur if it fails validation.
- **Pronunciation rules are optimistically cached under `["pronunciation", id]` and never refetch-invalidated** — same rationale as chapter exclusion, so a slow write cannot flash the table back; costs: a concurrent edit elsewhere only appears on the next book-page mount.
- **Reset progress confirms in a dialog, then clears `folio-pos-<id>` and navigates to chapter 1** — the server DELETE alone leaves this device's offline resume pointer behind, which would re-trigger the cross-device prompt; costs: "start from the beginning" means the first included chapter, not a saved segment.
- **Pronunciation rules apply sequentially, one regex pass per rule in creation order** — a later rule can rewrite text an earlier rule produced, which is what "order matters" means to the user; costs: rule order is part of the configuration.
- **`after_number` uses `(?:(?<=\d)|(?<=\d\s))`, not `(?<=\d\s?)`** — Python lookbehinds must be fixed-width; costs: at most one whitespace character may sit between the digit and the word.
- **The `tts` voice is filtered at the API list and in `select_voice`, not in `discover_voices`** — discovery keeps mirroring the engine truthfully while no selection path can ever pick the engine's internal fallback; costs: two places name the id.
- **A rule change deletes the book's `segment_audio` rows instead of re-queueing them** — the next `prepare` (playback) rebuilds the window with the corrected text and new cache keys, and old `audio` rows/files stay for eviction; costs: an idle book regenerates nothing until someone presses play.
- **`GET /books/{id}/pronunciation` requires admin-or-uploader like the mutations** — the rules are a book-settings surface and can quote book text; costs: plain listeners cannot preview which substitutions apply.
- **The service worker is a hand-written `public/sw.js` whose routing lives in one pure `routeFor(path, method, mode)` function** — no SW dependency is allowed, and evaluating the file with a fake `self` in `src/pwa.test.ts` tests the cache rules without a browser; costs: the test duplicates the function's signature.
- **SW caching policy: cache-first with background refresh for every same-origin GET except `/api/`, network-first for navigations with an `/offline.html` fallback, network-only for `/api/v1/audio/`, covers cached by URL** — enumerating Vite's hashed assets needs a build hook, and cache-on-fetch for non-API GETs achieves the same with no tooling; costs: a stale asset lives one background refresh, and API HTML errors are never cached.
- **The Finished shelf is a collapsed `<details>` at the bottom of the library page** — the spec gives it no dedicated screen and the cards are the grid's own; costs: finished books are one tap away, not a tab.
- **Edit / Book settings / Reprocess / Delete now key off `book.can_edit` with an `role === "admin"` fallback** — the M6 payload computes the flag server-side, but stacks with an older API must not lose the admin UI; costs: uploaders see nothing until the backend ships `can_edit`.
- **Chapter numbers in the book-page picker and the settings list are `idx + 1`** — excluded chapters must keep the number the player shows, so positional numbering was wrong; costs: numbers can skip when a chapter is excluded (that is the point).
